What is a CLI?

CLI stands for Command Line Interface. Instead of clicking buttons in a window, you type instructions as text. The computer responds line by line.

BROWSER (GUI) — A PRODUCT

  • You use what the company built
  • They decide what you can do and see
  • Your data lives on their servers
  • Context resets with every new chat
  • Copy-paste is your only bridge to your files

TERMINAL (CLI) — A TOOL

  • You run the software on your machine
  • No limits except your imagination and the tool's capability
  • Your files stay on your computer
  • The AI reads your actual project, not a summary you typed
  • You can chain tools: read, edit, run, test in one session
A browser is a product. A CLI is a tool. One serves you what someone else built. The other lets you build.
— Cambio Labs, AI Literacy Track
🔍

Why use a CLI for AI?

THE CONTEXT ADVANTAGE

When you use AI in a browser, you paste a question and maybe a file. The AI only sees what you give it in that text box.

When you use AI in a terminal, the AI sees your actual project. Your file structure. Your code. Your folder of notes. Your data exports. It reads everything you let it see.

IT SEES YOUR ACTUAL FILES

No more copy-paste. No more "imagine I have a file that does X." The AI just reads the file. It works with what is really there, not what you remembered to paste.

IT KEEPS WORKING WITH YOU

In a browser, each chat is a bubble. In a terminal, the session holds context across the whole conversation. You can ask follow-ups, make changes, run code, and the AI remembers what came before.

IT IS REPRODUCIBLE

Every command you run is text. You can save it, share it, re-run it. No "click the button in the top right then the dropdown then..." Just text that says exactly what happened.

IT WORKS OFFLINE

CLI tools can run local models. No internet required. No server deciding to change the UI or remove a feature. The tool is yours.

WARMUP The terminal can be fun

Before we do anything serious — the terminal is not all work. Try this:

$ cmatrix -r
That is the Matrix digital rain effect. The -r flag randomizes the colors. It does nothing useful. That is the point.
If you do not have cmatrix installed:
macOS:
$ brew install cmatrix
Linux:
$ sudo apt install cmatrix
Hit Ctrl+C to stop it. That is how you stop most running terminal programs.
This is the first thing you should do in a terminal: run something useless that feels cool. It breaks the fear of the blank screen.

TERMINAL BASICS The terminal reflects your folder structure

Every terminal session starts somewhere in your computer's folders. Think of it as a cursor moving through your file system.

Your first commands:
$ pwd
/Users/you/Documents

$ ls
Documents Downloads Projects notes.txt

$ cd Projects
$ ls
my-app blog ideas.md

$ cd ..
$ pwd
/Users/you
pwd = "print working directory" (where am I?)
ls = "list" (what is here?)
cd = "change directory" (go there)
cd .. = go up one folder
mkdir = "make directory" (create a new folder)

TERMINAL BASICS Create your own space

Make a folder to work in. This is where you will run the AI tool later.

$ mkdir ai-playground
$ cd ai-playground
$ mkdir notes
$ ls
notes
You just created a folder called ai-playground and inside it another folder called notes. This is your sandbox.
Think of it this way:
ai-playground/ ← you are here
└── notes/ ← you made this
Everything you do with the AI tool will happen inside this folder. Your files, your data, your context.
The terminal is just a text interface to the same files you see in Finder or File Explorer. Every file you see in the GUI, you can reach from the terminal.

WINDOWS WSL — Linux inside Windows

If you are on Windows, you get the best terminal experience through WSL — Windows Subsystem for Linux. It runs a real Linux environment inside Windows, no dual booting.

Install WSL (one time, 5 minutes):
$ wsl --install
Run that in PowerShell or Command Prompt as Administrator. It installs a full Ubuntu terminal on your machine.
After install:
  • Restart your computer
  • Open "Ubuntu" from the Start Menu
  • Create a username and password (for the Linux environment)
  • You now have a terminal that works exactly like macOS or Linux
Your Windows files are at /mnt/c/Users/you inside WSL. You can access everything, but it is faster to keep your project files inside the Linux filesystem (your home folder).

STEP 1 Install OpenCode

Now you put the AI tool into your terminal. One command:

$ curl -fsSL https://opencode.ai/install | bash
That downloads and installs the opencode binary — an open source AI coding agent. No Node.js needed. It is a compiled Rust program, about 40MB.
Other install methods:
npm:
$ npm install -g opencode-ai
Homebrew:
$ brew install anomalyco/tap/opencode
📷

STEP 2 Confirm it landed
$ opencode --version
0.82.0
If you see a version number, you are done installing.
If you get command not found, restart your terminal. The install script adds OpenCode to your PATH, but the change only applies to new terminal sessions.
Bonus: Because OpenCode is a single binary, you can put it on a USB drive and run it on any machine. No installers, no runtimes, no dependencies.

STEP 3 Connect an AI provider

OpenCode is the engine. It still needs a model to talk to.

$ opencode

> /connect
The /connect command shows a list of providers.
Easiest option — use your existing accounts:
  • GitHub Copilot: Log in with your GitHub account
  • ChatGPT Plus/Pro: Log in with your OpenAI account
  • OpenCode Zen: Sign up at opencode.ai/auth, pay-as-you-go
  • API key: Paste an Anthropic, OpenAI, or Google key directly
75+ providers supported. Including local models via Ollama — no internet, no cost, runs entirely on your laptop.

STEP 4 Initialize in your project

Navigate to the folder you created earlier and start the AI:

$ cd ai-playground
$ opencode
Then tell OpenCode to learn about this folder:
> /init
OpenCode scans the folder and creates an AGENTS.md file that stores project context. Every time you come back, it remembers what this project is about.
This is the context advantage in action. The AI now knows exactly what is in your folder. Not a summary you typed. Not a file you remembered to attach. The actual contents.

STEP 5a Talk to your project

You can ask OpenCode about anything in your folder. No copy-paste needed.

> What is in my notes folder?
[reads the folder and summarizes the files...]
OpenCode reads files directly from your disk. It is not guessing based on what you pasted into a text box.
Use @ to point to specific files:
> Summarize @notes/research.md and tell me what is missing
The @ key opens a fuzzy file finder. Start typing and it jumps to the right file.

STEP 5b Plan first, build second

Press Tab to switch to Plan mode. The AI will explain what it would do without touching anything.

[Plan mode — status bar says "plan"]
> Create a file called ideas.md with 5 venture ideas
  based on the notes in my notes folder.
OpenCode describes the plan without writing anything...
Review the plan. If it looks right, press Tab to switch to Build mode:
> Go ahead.
[creates ideas.md with the content]
Plan mode is the safety net. Use it until you trust what the AI will do.

STEP 5c Undo, redo, and share

OpenCode tracks every change. If the AI does something you did not want:

> /undo
Reverts the last change. Run it multiple times to walk back further.
> /redo
Reapplies the last undone change.
Share your session with someone:
> /share
→ https://opencode.ai/s/4XP1fce5
Creates a link to the entire conversation. Anyone with the link can see what you asked and what the AI did.

STEP 6 Customize

OpenCode is built to be adapted to how you work.

  • Themes: /theme to switch look and feel
  • Custom commands: Add your own /commands to the palette
  • Keybinds: Remap every shortcut in opencode.jsonc
  • LSPs: Auto-loads language servers for syntax-aware editing
  • Images: Drag and drop screenshots or mockups into the prompt
Config file location:
~/.config/opencode/opencode.jsonc
The config is a JSON file with comments (.jsonc). You can edit it by hand or use the /config command.

TROUBLESHOOTING When something does not work
Problem Try this
opencode: command not
found		 Restart your terminal. If that does not fix it, check ~/.opencode/bin is in your PATH. On Windows, use WSL.
curl install fails Try npm: npm install -g opencode-ai. Or download the binary from GitHub releases.
No provider shows in
/connect		 Run /connect again. The list loads from the network. If you have a key, add it manually in opencode.jsonc.
Model is too slow or
keeps erroring		 Switch providers. Zen gives curated, fast models. Ollama gives free local models.
AI does not understand
my project		 Run /init again. You can also edit AGENTS.md by hand to add more context.
I broke something
and need help		 Run /share and send the link to a TA or teammate. Or ask at opencode.ai/discord.
You will not break anything permanent. Every change can be undone with /undo. The terminal is not fragile — it is the most resilient tool on your computer.
